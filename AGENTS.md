# AGENTS.md

## What this repo is
- Audio → event IR → **maidata** (simai/maimai DX) toolkit. P0/P1/P2 are implemented. P3 v0 training/inference code exists in `src/mainote/ml/`, but no checkpoint is trained or shipped. P3 v0 uses architecture v2 (embedding scaling, final LayerNorm, stride-2 audio frontend), default sampling decode, window-normalized weighted token CE, note-level validation for checkpoint selection, manual tempo-map support, and no cross-window Hold/Slide state.
- A local web UI (`mainote web`) wraps browsing, the official MajdataView WebGL preview, online chart downloads, inference, and training jobs. The training page can select songs from a processed dataset, export samples/log-mel features for just that selection, override training hyperparameters, and preview the model layer stack. The dataset page shows per-song sample/feature readiness and can backfill missing data in one click. Backend is FastAPI in `src/mainote/webapp/`; frontend source is `web/` (React + MUI + Vite); the built bundle is committed under `src/mainote/webapp/static/`.
- The dataset page can search and download charts from AWMC-MaiArchive (`https://download.wmc.pub/`) via its public JSON API and import them as `wmc_<shortid>` songs. The same flow is available from the CLI (`dataset fetch-wmc`).
- Core invariant: generators produce `Event` IR; `src/mainote/maidata/compiler.py` owns all maidata formatting (`{n}`, commas, `[a:b]`, `E`). Do not generate raw maidata text directly.
- `MAIDATA_FORMAT.md` is the format reference. `AUDIO_TO_MAIDATA_PLAN.md` is the design plan and now uses the code's canonical units (960 ticks/beat, 3840 ticks/bar). Trust code and tests when they disagree.
- P3 workflow is documented in `docs/TRAINING.md`; training must run on a GPU server, not in this CPU-only workspace.

- Full test suite (audio tests need numpy; web tests need `.[web]`): `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v` (154 tests).
- P0-only tests: `PYTHONPATH=src python3 -m unittest discover -s tests` (numpy/torch/web-extra tests skip).

- Online catalogue from the CLI: `mainote dataset fetch-wmc -q Apollo --limit 5` or `--id 011661`; downloads cache under `out/wmc-cache/`, imports into `data/raw/wmc_<id>/` + `data/processed/wmc_<id>/`. Use `--dry-run`, `--align`, `--include-video`, `--force`, `--delay`.
- Demo: `PYTHONPATH=src .venv/bin/python scripts/make_demo.py out/demo`
- Audio, demo, and `dataset ... --align` require `.venv/bin/python`; system `python3` has no numpy. The editable `.venv/bin/mainote` entrypoint also exists.
- P3 commands (on a GPU server with `.[audio,train]`):
  `mainote ml prepare-features ... [--songs a,b]`, `mainote ml prepare-data <processed_dir> --songs a,b`, `mainote ml train --config configs/p3_base.yaml`, `mainote ml infer --checkpoint ... --audio ... -o ...`.
- P3 needs `torch`/`pyyaml` (the `train` extra). This workspace has CPU-only PyTorch for smoke tests; use a GPU server for real training.
- Web UI: `pip install -e '.[web]'` then `mainote web [--host 127.0.0.1] [--port 8765] [--no-browser]`. Frontend dev: `cd web && npm run dev` (Vite 5173 proxies `/api` to 8765); `npm run build` writes `src/mainote/webapp/static/` and runs `tsc --noEmit` first.
- No lint/typecheck/CI config; verify with unittest plus `PYTHONPATH=src python3 -m compileall -q src tests scripts` and `cd web && npm run typecheck`.
- If pip cannot resolve packages, use a domestic mirror, e.g. `-i https://pypi.tuna.tsinghua.edu.cn/simple`; for npm use `--registry=https://registry.npmmirror.com`.

## Layout
- `src/mainote/maidata/`: `model.py` (IR, tick constants, `Event.chain_type`), `parser.py`, `compiler.py`, `validate.py`, `stats.py`.
- `src/mainote/audio/`: ffmpeg decode + numpy onset/BPM/beat analysis; `TimingInfo` JSON. Keep this frontend numpy-only unless there is a strong reason.
- `src/mainote/generate/rule.py`: hand-tuned rule baseline; `DIFFICULTY_RULES` and `LEVEL_DENSITY_ANCHORS` are priors, not learned truth.
- `src/mainote/dataset/`: `ingest`, `align`, `report`, `split`, `samples`, shared zip import (`zipimport.py`), and the stdlib AWMC-MaiArchive client (`wmc.py`).
- `src/mainote/eval/metrics.py`: note-level comparison (onset F1, position/type, duration, slide endpoints).
- `src/mainote/ml/`: P3 v0 tokenizer (strict grammar constraints for decoding), log-mel features, window dataset (LRU caches, overlong-window rejection), model (architecture v2), train loop (weighted window-normalized CE, per-class and note-level validation), constrained sampling/greedy decoder, inference. No auxiliary losses or candidate reranking yet.
- `configs/p3_base.yaml`: base training config.
- `src/mainote/webapp/`: FastAPI app (`app.py`), dataset catalog/chart serialization (`catalog.py`), one-at-a-time subprocess jobs (`jobs.py`), zip dataset import (`datasets.py`), background online-catalogue import jobs (`wmc.py`), option/run scanners (`options.py`), path allow-listing (`settings.py`), training data selection/config overrides (`training.py`), torch-free model layer descriptions (`architecture.py`), MajdataView audio helpers (`viewer.py`), the vendored MajdataView WebGL build plus its bridge (`majdataview/`), and built frontend assets (`static/`).
- `web/`: React 18 + MUI 6 + Vite + TypeScript frontend (`src/pages`, `src/components`, `src/api.ts`, `src/types.ts`). `npm run build` writes into `src/mainote/webapp/static/`.
- `docs/TRAINING.md`: server data prep, training, inference, evaluation, troubleshooting.
- `tests/`: stdlib `unittest`, not pytest.

## Dataset / training samples
- Raw layout: `data/raw/<song_id>/{audio.*,maidata.txt,meta.json?}`.
- Online imports use one zip per chart (background video excluded by default), copy `maidata.txt` + `track.*` + `bg.*` into `data/raw/wmc_<shortid>/`, and cache downloads under `out/wmc-cache/` (CLI) or `out/webui/cache/wmc/` (web). The web UI and CLI share `dataset/zipimport.py`.
- `dataset ingest --align` → `data/processed/<song_id>/{meta.json,maidata.ir.json}`. One IR per song keeps all difficulties and shares audio.
- `dataset samples --splits ... --require-audio` → one sample per `(song_id, inote_N)`:
  `data/samples/<song_id>/inote_N.json`, `manifest.jsonl`, `summary.json`, `splits.json`.
- `manifest.jsonl` fields include `sample_id`, `chart_index`, `difficulty`, `level_num`, `audio`, `ir`, `first`, `initial_bpm`, `event_count`, `stats`, `alignment_confidence`, `valid`, `split`. `valid` is **per chart**: `meta.json` keeps song-level `errors`, but `export_samples` recomputes `validate_chart` for each difficulty and only carries non-chart errors forward, so one broken difficulty does not invalidate the others. Training/manifest filtering drops invalid charts individually.
- Split **by song only**; all difficulties of a song stay in one split. Never split by chart or window.
- Ingest stores absolute audio/IR paths; moving the dataset requires re-ingest.
- `dataset samples` does not replace `maidata.ir.json`; the IR remains the source of truth, sample files are chart-level training views.
- P3 training also needs `mainote ml prepare-features data/processed --out data/features`; each song becomes `data/features/<song_id>.npz` (mel, fps, sr, n_mels, duration).
- Web training selection re-splits **only the selected songs by song** and writes `runs/<run>/training_manifest.jsonl`; hyperparameter overrides deep-merge into `runs/<run>/train_config.yaml`, leaving `configs/` untouched. If the selection has no val song, `train.note_eval.enabled=false` and `checkpoint_metric=val_loss` are set automatically. `mainote ml prepare-data <processed_dir> --songs ...` exports samples and features for only the selected songs in one job.

## Gotchas
- `B2` is Touch, `2b` is Break; `E1` is Touch, `E` is End; `1/8` is EACH, `1-5` is Slide. See `MAIDATA_FORMAT.md`.
- Parser supports `*` same-start chains and connected path slides (`4-1>2-7[16:7]`) via `Event.chain_type` (`same_start` / `path`). A `*` chain where a branch is itself a path is `chain_type="mixed"`; `SlideSegment.branch` records the branch, and each branch keeps its terminal duration on its last segment. A `*` may also terminate a path (`8-2v3-5[4:1]*-5[4:1]`): the next segment starts again from the original star point and must become a new branch, not a continuation of the path's last position. Do not collapse these cases.
- `[1:0]` is legal simai (zero-length duration) and appears in official charts. It parses to `Duration(ticks=0)` and must survive compile and validation. `[#seconds]`/`[wait##seconds]` durations are wall-clock time, so hold-overlap validation must convert them through the chart tempo map (`seconds_at_tick` + `ticks_at_seconds`), not the BPM at the start tick — official charts change BPM under long holds.
- AWMC-MaiArchive integration only talks to fixed hosts (`download.wmc.pub`, `oss.awmc.cc`), validates numeric 5–7 digit shortids, and never accepts a browser-supplied URL. Search/detail use `/api/v1/charts`, zips use `download.zipNoVideo` (or `zip` with `--include-video`); retries cover transient 5xx/timeouts. The HTML pages need a guard cookie, but the API does not.
- `Duration.raw` preserves odd `[...]` forms in IR JSON but is excluded from semantic round-trip signatures. Compare semantic fields, not raw formatting.
- Compiler groups all `&lv`/`&des` before all `&inote` bodies and keeps generated metadata minimal (`title`, `artist`, `wholebpm`; no `&first=0`/`&clock_count`). This is reader-compatibility behavior; do not revert casually.
- The committed `dataset/xxdw/maidata` is the only fixture: 4 charts, BPM 143, no audio. Use it for parser/compiler goldens.
- `out/`, `data/raw/`, `data/processed/`, `data/features/`, `data/samples/`, `runs/`, `assets/synthetic/`, `.venv/`, and audio files are gitignored. `audio-FM/` is local user audio; never commit it.
- The current machine has no GPU and there is no training checkpoint. Do not claim a trained neural model exists.
- P3 tokenizer uses 20-tick units (1/48 beat, 192 per 4/4 bar); IR ticks must be multiples of 20 for lossless tokenization. `MAX_LEVEL_BUCKET=31` represents 15.5 (`15+`); levels above 15.5 clamp to that bucket.
- P3 architecture v2 (`embed_scale`, `final_norm`, `audio_stride=2`) is not checkpoint-compatible with v1; retrain. Strict grammar mode (`ChartTokenGrammar(strict=True)`) is for decoding; permissive mode must keep parsing existing charts.
- Difficulty priors are not calibrated: `LEVEL_DENSITY_ANCHORS` ends at 15.0 and `profile_for_difficulty` clamps density to per-difficulty bands, so master/remaster saturate. Do not promise 13–15/15+ fidelity until P2.5 calibration.
- Auto BPM (`audio/features.py::estimate_tempo`) expands autocorrelation peaks by metrical ratios (`1, 2, 1/2, 3/2, 2/3, 4/3, 3/4`) and scores them with a 165-BPM log-normal chart prior (sigma 0.6 octaves, range 60–260 BPM). Confidence is the score margin to the next tempo ≥8% away. `TimingInfo.bpm_candidates` is serialized in timing JSON; `analyze` and `ml infer` print/emit a warning below `BPM_LOW_CONFIDENCE=0.2`. Audio-only octave ambiguity is not fully solvable (e.g. 250 vs 166.7, 220 vs 147), so `--bpm N --first S` remains the escape hatch; on the local 63-song corpus this picks the reference tempo for 55 songs (up from 31 with the old 130-BPM prior).
- If real-song BPM/downbeat is still wrong: `analyze --bpm N --first S`, then `generate --timing timing.json`.
- Do not hand-edit `src/mainote/webapp/static/`; run `cd web && npm run build`. The UI never sends arbitrary shell commands: `JobManager` only spawns `mainote ml train|infer` plus `ml prepare-data`, one job at a time, and `WebSettings.resolve_under` rejects paths outside the repo / `runs/` / `out/`. UI hyperparameters are whitelisted and range-checked in `webapp/training.py`. Keep these invariants when adding endpoints.
- The viewer embeds the unmodified official MajdataView WebGL build under `src/mainote/webapp/majdataview/` (GPL-3.0; keep its `LICENSE`). `mainote-loader.js` prefetches the compiled chart, mp3 and optional background, intercepts the build's hidden `#fileuploader` click, and calls `SendMessage('GameMain','ChickLoad')` repeatedly to advance the chart → audio → background stages; the build runs with `autoload=1`. The build's difficulty selector defaults to slot 0, so the backend compiles the selected chart into `&inote_1`/`&lv_1` (`VIEWER_DIFFICULTY_INDEX`). The build decodes audio as MPEG only; `viewer.py` transcodes to cached mp3 (or generates silence). Do not replace this with a hand-written playfield approximation.
- The viewer's in-iframe control bar (markup/CSS in `majdataview/index.html`, logic in `mainote-loader.js`) provides play/pause (`SendMessage('GameMain','TogglePlay')`), a wall-clock progress slider, and this song's difficulty chips. Difficulty/seek choices are posted to React (`mainote:majdataview-difficulty` / `mainote:majdataview-seek`), which updates the URL and reloads the iframe. **Seek is server-side rebasing:** `/api/majdataview/maidata?seek=S` drops events that start before S and shifts `&first` by `-S`; `/api/majdataview/audio?start=S&duration=D` trims the mp3 with ffmpeg `-ss`; after reload the game starts at time 0 with correct relative note timing. `SimaiProcess` only reads the global `&first=` (per-chart `&first_N` is ignored), so `catalog._viewer_text` strips every first metadata entry and lets the compiler emit one global value. Seek/difficulty reloads require pressing Play again (browser audio activation), and progress is wall-clock time, so MajdataView speed settings can desync it.
- The browse page (`BrowsePage.tsx` + `CoverFlow.tsx`) mirrors MajdataView_web's `SongLstMenu` song-select carousel, not a generic gallery: full-bleed pastel stage sampled from the reference `color.png` (`#ffbafd` → `#ded0ff` → `#bde7ff`, 38deg), nine covers, centre scale 10.8 vs side 7.8 at 3.3-unit spacing (hence `CARD_SHIFT = 3.3/10.8`, `SIDE_SCALE = 7.8/10.8`), 0.5s eased movement, A/D and arrow keys, and `View` entering the viewer. Local libraries ship no jacket images, so `CoverArt.tsx` generates deterministic sleeves from `coverTheme()` in `Jacket.tsx`. "全部曲库" merges all existing roots, the selection is mirrored to `?root=&song=` so returning from the viewer restores it, and cover dim persists in localStorage. Note speed and offset live in MajdataView's own settings, not in the React UI.
- Browse roots default to `data/processed`, `out/demo/processed`, `out/audio-fm/dataset/processed`; override with `MAINOTE_WEB_DATA_ROOTS` (`:`-separated).
- Web dataset import (`POST /api/datasets/import`, multipart `files`) treats one zip as one song: it validates archive members (`..`, absolute paths, symlinks, encryption, size), copies only the located audio/maidata/background into `data/raw/<unique_id>/`, then runs `ingest_dataset` into the first browse root (`data/processed` by default). Duplicate ids get `_2` suffixes; failures are reported per zip and do not abort the batch. Add `align=true` to analyze BPM/alignment. A failed ingest removes its raw song directory so retries do not accumulate `_2` copies.
- `GET /api/datasets` adds `sample_ready` / `features_ready` to each song by reusing `training_catalog`; the dataset page uses those flags for its readiness chips and its “补全样本与特征” action. That action only posts song ids to `POST /api/train/prepare` (the same `ml prepare-data` job), so online imports can be made trainable without visiting the training page.
- Training UI endpoints are `GET /api/train/data?root=`, `GET /api/train/config?path=`, `GET /api/model/architecture` (torch-free shape/parameter estimates), and `POST /api/train/prepare`; `POST /api/train/start` accepts `song_ids`, `root`, `features_dir`, `hyperparams`, `seed`, and `val_ratio`. The server rewrites a per-run manifest/config under `runs/<run>/`; it never edits `configs/` and never accepts raw CLI arguments from the browser.
- Online catalogue endpoints are `GET /api/wmc/search`, `GET /api/wmc/cover/{shortid}?image=...`, `POST /api/wmc/import` (`{ids, align, include_video, force}`), `GET /api/wmc/imports[/{id}]`, and `POST /api/wmc/imports/{id}/cancel`. Imports run in one background thread (one job at a time, max 100 songs) and are polled by `DatasetPage`/`OnlineCatalogue.tsx`.
- Online covers are the archive's square `bg.png`: search results get a `cover_url` pointing at the proxy, which caches images under `out/webui/cache/wmc/covers/` and only accepts validated 5–7 digit ids plus image basenames. Local songs expose `cover_url` through `/api/majdataview/bg` (processed dir or `meta.raw_dir`). `Jacket`/`CoverArt` render the real image and fall back to the generated sleeve on error.
